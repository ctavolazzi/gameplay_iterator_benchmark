# Playbook v005o

Written 2026-10-03 by one of two coaches given the same task: start from v004, read its
stored runs (22, 24, 25, 26), and write a playbook that reaches all 11 milestones in fewer
decisions and fewer game ticks, with no failed actions and no damage. The model is
Qwen3.5-0.8B; seed `7040093665601660210`; 16 decisions per run. This coach worked alone and
did not read v005s.

## Where v004 lost time (read from the steps and events rows)

1. **The furnace walk.** In 22, 24 and 25 `make_furnace` walked 75 seconds toward a table 19
   to 26 blocks off and far above, timed out, then needed an `explore` and a second
   `make_furnace`: about 85 seconds and 2 decisions each. In 26 the table ended up more than
   32 blocks away, no table could be made (3 planks left), and the furnace never came.
2. **The stone pickaxe walk.** The table was 10 to 12 blocks off when the stone pickaxe was
   made in 3 of the 4 runs; that craft took 26 s (run 22) and 16 s (run 24).
3. **Too much iron.** `mine_iron` dug for 3 raw iron. One is the milestone. It took 2
   decisions in 22, 24 and 25, and 53 to 58 seconds in one of them.
4. **One decision per craft.** Planks, sticks, the table and the wooden pickaxe were four
   decisions, each about 3.5 s of model time plus the game's own work.
5. **"Lost" sticks.** Run 24 had 2 sticks before `mine_stone` and none after, spent a
   decision on `make_sticks`, and then carried 6. The sticks were never gone: what the game
   reports as carried had gone stale. Run 28 showed the same with logs (below).

## What v005o changes

- Every craft that needs a table puts one down where the bot stands when no table is within
  8 blocks (the adapter has offered `place:crafting_table` there since commit 340b5b3).
- `get_wood` collects 5 logs, not 3: the first table, sticks, the wooden pickaxe, and a
  spare table each for the stone pickaxe and the furnace.
- A craft makes the planks, sticks and table it needs on the way, so the wooden pickaxe is
  two decisions from empty hands (`get_wood`, `make_wooden_pickaxe`).
- `mine_iron` stops at one raw iron, and tries the next ore when a drop is not picked up.
- `get_wood` keeps to one kind of tree: the recipes in minecraft-data 26.1 are per wood
  type, so 2 oak planks and 2 birch planks do not make a table.
- A skill that failed is left off the next menu.
- After the goal, `rest` (does nothing) is the only option, in place of v004's endless
  `explore:north`.
- After run 28: `get_wood` after the first pickaxe only when no other job can be done, and
  the skills read results of their own actions instead of calling `observe()` and
  `primitives()` before each one (about a second each).

## What needs the adapter, not the playbook

- **Carried items go stale.** Items vanish from `observe().carrying` and come back after a
  later dig (run 24 sticks, run 28 logs, run 31 a second crafting table that appeared during
  `mine_coal`). Any skill that plans from counts is misled.
- **`collect()` ends its pickup on any gain.** Dirt dug on the way counts as "picked up", so
  the ore's own drop is left behind (run 28, iron and coal; 10 to 20 seconds each).
- **No reason recorded when a table is not placed** in the place-or-walk case of run 31. The
  adapter's `placeTable` only tries 4 spots and needs open ground; a pit may have none.
- **Every `observe()` and `actions()` searches the world again**, about a second on this Mac.
  A skill pays it once per action just for the legality check.

## What I would do next

1. Read the placement note from the next run before changing anything about tables.
2. Ask for the adapter fixes above, the drop pickup first: it is the largest remaining loss
   that the playbook cannot touch.
3. The first decision is the slowest part of every run (35 to 46 s for 5 logs, most of it
   walking and path planning to the first tree). A 4 log start would save one dig but leave
   only one spare table. Run 31 crafted both spares (one placed, one not); runs 28 and 32
   crafted one. The v004 runs had the table 10 to 12 blocks off at the stone pickaxe in 3 of
   4, so I would keep 5.
4. With the goal reached at decision 7 or 8, the remaining 8 decisions are `rest`. The next
   goal (smelting, an iron pickaxe) needs adapter actions that do not exist yet: placing a
   furnace and using it.
